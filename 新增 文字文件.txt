投影片 3 – 專案動機
• 現有即時字幕方案（Google Speech API）需依賴網路
• 離線語音辨識引擎（Vosk）精準度不足
• 課堂、會議等場景需要即時關鍵詞提取
• 希望打造一套「全離線、高精準、低延遲」的字幕系統
投影片 4 – 系統目標
• 即時麥克風收音與語音辨識
• 離線運作，不依賴網路
• 左右分割介面：關鍵詞 + 通順語句
• 支援 GPU 加速與 CPU 備援
• 內建防禦機制對抗 AI 幻覺
• 歌詞 / 領域詞彙校正比對
• OBS 動態字幕輸出

投影片 8 – 音訊擷取：PyAudio
• 取樣率：16000 Hz（Whisper 標準輸入）
• 聲道：單聲道 (Mono)
• 位元深度：16-bit signed integer
• 緩衝區：2000 samples per chunk
• 音量計算：RMS = sqrt(mean(square(audio_data)))
• 自動偵測系統預設麥克風
投影片 9 – 語音辨識引擎：Faster-Whisper (1)
• 基於 OpenAI Whisper 架構
• 使用 CTranslate2 推論引擎（速度提升 4x+）
• 支援模型：tiny / base / small / medium / large
• 本系統使用：small（460MB），兼顧速度與精度
• 自動語言偵測與指定（固定繁體中文 zh）

投影片 11 – GPU 加速與備援機制
• 優先嘗試 NVIDIA CUDA + float16
• 若 GPU 不可用，自動降級 CPU int8 量化
• 完全無縫切換，使用者無感
• 首次啟動自動下載模型檔案
• 快取機制：第二次啟動無需重載

lazy_load_model():
  try: model = WhisperModel("small", device="cuda")
  except: model = WhisperModel("small", device="cpu", compute_type="int8")
投影片 12 – 關鍵詞提取：jieba TF-IDF
• 使用 jieba 分詞 + TF-IDF 演算法
• 提取 top-5 關鍵詞（名詞 n、動名詞 vn、動詞 v）
• allowPOS 過濾詞性，保留實詞
• 不保留單字，降低雜訊

keywords = jieba.analyse.extract_tags(
    text, topK=5, allowPOS=('n', 'vn', 'v')
)
投影片 13 – 歌詞校正機制：match_lyrics
• 解決 Whisper 對特定領域詞彙辨識不佳的問題
• 建立歌詞 / 專有名詞對照庫
• 模糊字元比對：找出最相似的正確句子
• 門檻值 0.3（30% 匹配即校正）
• 不匹配則保留原始 Whisper 輸出

match_lyrics(text):
  for line in lyrics_lines:
    score = common_chars / max(len(text), len(line))
    if score > 0.3: return line
  return text
投影片 14 – 智慧斷句與 VAD 語音偵測
• 環境噪音適應：RMS < 160 判定為靜音
• 連續 10 次靜音（約 1.2 秒）+ 緩衝區 > 32000 → 觸發辨識
• 最長 8 秒強制切斷（避免講者不停就沒字幕）
• Whisper 內建 VAD Filter：
  - min_silence_duration_ms = 500
  - threshold = 0.3
• 雜訊閘：|audio| < 0.003 直接歸零
投影片 15 – 防護機制：AI 幻覺攔截
三層防禦架構

第一層：VAD + no_speech_threshold = 0.7
  → 過濾非語音片段

第二層：log_prob_threshold = -0.5
  → 只保留高 confidence 結果

第三層：Regex 重複字偵測
  if re.search(r'(.)\1{3,}', text):
    → 判定為幻覺，直接丟棄
投影片 16 – 音量條與 OBS 輸出
• 即時音量條（綠色 ttk.Progressbar）
• RMS 映射至 0-100，視覺化收音狀態
• OBS 動態字幕：
  - 每次辨識結果自動寫入 obs_subtitle.txt
  - OBS 文字來源讀取該檔案
  - 覆寫模式：只保留最新一句
  - 零設定，開箱即用
投影片 17 – 精度提升歷程 (1)：初始狀態
Vosk small 模型：
  • 詞彙覆蓋率：83.7%
  • 環境噪音：大量 ... 空結果
  • 歌詞辨識：完全無法正確輸出
  • 反應時間：約 3-5 秒

首次改善：切換 Faster-Whisper base
  • 辨識率顯著提升
  • 但仍存在幻覺與重複問題
投影片 18 – 精度提升歷程 (2)：參數調校
參數調校迭代：

beam_size:     預設 5  → 10   （搜尋更廣）
temperature:   預設    → 0.0  （貪婪解碼）
patience:      預設 1  → 2.0  （更徹底）
length_penalty:預設 1  → 1.2  （完整句）
repetition_penalty: 1 → 1.1  （減少重複）
compression_ratio: 2.4 → 2.0（嚴格篩選）
log_prob_threshold: -1 → -0.5（高信賴）
投影片 19 – 精度提升歷程 (3)：最終參數
最終調整：

no_speech： 0.6 → 0.7           （更積極過濾）

投影片 22 – 遇到的挑戰與解決方案
挑戰 1：Vosk 模型詞彙不足
  → 解決：改用 Faster-Whisper

挑戰 2：GPU 環境不穩定
  → 解決：try/except 自動降級 CPU

挑戰 3：Whisper 幻覺（重複字/提示詞洩漏）
  → 解決：三重防禦 + Regex 偵測

挑戰 4：歌詞專有名詞辨識差
  → 解決：match_lyrics 模糊比對校正

挑戰 5：句子堆積延遲
  → 解決：智慧斷句 + 8秒強制切斷
